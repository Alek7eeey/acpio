# Цикл до цели

Точка остановки — цель, а не конец шага. План, пересказ и вопросы — работа, которая стоит пользователю хода: трать их один раз, в начале.

## До первого шага

Запиши цель как проверку, которую можешь запустить: команда и порог (`npm run eval → ΔV ≤ 0.5%`, `npm test → зелёный`, `IoU ≥ 0.99`). Без неё цели нет, есть только активность — сначала почини проверку.

Спрашивай пользователя, только если цели нужно то, что можешь дать лишь он: какой из вариантов имеется в виду, порог, который в просьбе нигде не назван, файл или доступ. Одно сообщение, все такие вопросы сразу, и больше никогда. Всё остальное — неизвестная причина, выбор между двумя подходами, число для подстройки — решаешь и записываешь ты.

## Итерация

Одно изменение, его проверка, одна строка: `#4 1452 → 380 мм³ — полосы по петлям вместо площади`. Затем сразу следующая итерация. Не заканчивай ход тем, что собираешься сделать, что проверишь дальше, или вопросом, приглашающим одобрение, которого никто не просил.

Ход заканчивается ровно по трём причинам:

- проверка проходит — назови число и остановись;
- блокер, который может снять только пользователь — назови одной строкой, чего не хватает, и остановись;
- пользователь тебя остановил.

Ничто в харнессе не требует паузы между шагами: прогон ограничивает кнопка Stop у пользователя, так что «сэкономить пользователю шаг», остановившись раньше, — это обратное тому, о чём просили.

## Когда итерация не удалась

- Одна и та же причина дважды → другая гипотеза, а не повтор того же прогона.
- Две итерации без движения в метрике → выпиши три возможные причины, проверь самую дешёвую, продолжай. Вопрос — не один из ходов.
- Тот же подход, падающий третий раз, — это блокер: скажи, какие три ты исключил и что тебе нужно.
- Никогда не двигай порог, не ослабляй проверку и не называй частичный результат успехом, чтобы закончить. Недостижимая цель с числами, показывающими почему, — честный конец, а сниженная планка — нет.

## Пока включены другие скиллы

Дисциплина ponytail по-прежнему решает, сколько кода нужно изменению; этот скилл решает, когда ты останавливаешься. Его завершающая строка («что пропустил») — план для следующего прогона; под этим скиллом завершающая строка становится журнальной строкой итерации.
