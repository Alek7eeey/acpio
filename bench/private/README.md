# Приватный eval: задачи из реальной работы

Публичные корпусы отвечают на вопрос «может ли агент чинить чужие баги по
чужому ишью». На вопрос «как он справится с **нашей** повседневностью»
честно отвечает только eval, собранный из собственных инцидентов и сессий:
нулевая офф-дистрибуция по определению. Здесь живут такие задачи.

## Откуда брать

- Коммиты этого репо с формулировкой «починили то-то» в теме — каждый такой
  коммит = один реальный сбой, который агент мог бы предотвратить.
- Разборы прогонов в `bench/results/*.md` (секции Failures, SKIP-списки в
  `bench/baseline.mjs`) — зафиксированные дефекты инфраструктуры бенча.
- Реальные сессии: если сессия потребовала у человека больше одного уточнения
  или одного перезапуска — это кандидат в задачу.

## Пайплайн одной задачи

1. `node bench/private/extract.mjs <commit> <task-id>` — скаффолдит каталог
   с заметками из коммита (тема, тело, затронутые файлы).
2. **Деидентифицировать**: в задаче остаётся только форма сбоя (механика),
   никаких внутренних URL, имён сервисов и заказчиков. Fixture — маленькая
   синтетическая репродукция той же механики, не снапшот боевого кода.
3. Написать `task.json` (промпт — как сформулировал бы человек, не автор
   фикса), `fixture/`, скрытый `verify.mjs`, `solution/`.
4. Прогнать `node bench/selftest.mjs --only <task-id>` — «на баге падает /
   на gold проходит» обязательно, иначе задача не считается.

## Правила

- Задачи запускаются только через `--tasks-root bench/private/tasks` — в
  дефолтный sweep и docker-контур они не попадают.
- Расхлебённые места (то, что мы чинили дважды) ценнее красивых багов.
- Одна задача = один навык. Если в инциденте было два урока — две задачи.
- Всё, что агент мог узнать из истории git этого репо, — для нас не утечка:
  все сравниваемые агенты стартуют с одинаково известного материала.
