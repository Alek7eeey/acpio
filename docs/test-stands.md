# Тестовый стенд (локальная копия для проверок)

Стенд — это отдельный процесс приложения со **своей** БД, чтобы эксперименты,
скриншоты и прогоны агентов не трогали рабочий профиль.

```bash
# 1. Своя БД + свой порт (иначе подхватится чужой PORT из окружения)
DATABASE_PATH="$PWD/tmp/stand/acpio.db" ACPIO_PORT=18741 npm run dev:server
ACPIO_PORT=18741 npm run dev:web          # UI на http://localhost:18751
```

## Правила стенда

1. **Cursor выключен всегда.** Иначе сервер при старте пробует `cursor-agent`,
   тот открывает браузер и упирается в проверку входа — посреди чужой работы.
   Ставится сразу после первого запуска:

   ```bash
   curl -sS -X PUT http://127.0.0.1:18741/api/settings \
     -H 'Content-Type: application/json' \
     -d '{"disabledProviders":["cursor"],"defaultProvider":"builtin"}'
   ```

   Проверка, что выключен (без запуска агента):

   ```bash
   curl -sS 'http://127.0.0.1:18741/api/agent/models?provider=cursor'
   # → {"ok":false,…,"message":"Агент \"Cursor\" отключён в настройках"}
   ```

2. **Модель для проверок — своя строка провайдера** (`builtinProviders`), а не
   чужой профиль: у неё есть `models[].efforts`, и агент показывает уровни
   эффорта так же, как в бою.
3. **Секреты не в БД стенда, если стенд переживёт задачу.** Ключ, положенный в
   `tmp/…/acpio.db`, считается сгоревшим — стенд удаляется вместе с ним.
4. **Скриншоты — только со стенда.** Рабочая БД содержит чужие чаты, папки и
   ключи; снимать UI с неё нельзя.
5. **Погасить за собой:** стенд живёт в фоне и держит порт 18741/18751 —
   следующий запуск упадёт с `Port is already in use`.

## Что уже наступало

- `PORT=3002`, унаследованный от другого инструмента, уводил сервер с 18741 —
  Vite проксировал в пустоту, UI показывал «Reconnecting…» и `Failed to fetch`.
  Лечится явным `ACPIO_PORT`.
- Service worker отдавал старый бандл после перезапуска Vite: страница
  выглядела живой, но говорила со стендом, которого уже нет. Перед проверкой —
  `navigator.serviceWorker.getRegistrations()` → `unregister()` и перезагрузка.
- Параметры модели в пикере кэшируются на клиенте: после смены настроек
  провайдера список уровней обновляется только после перезагрузки страницы.
