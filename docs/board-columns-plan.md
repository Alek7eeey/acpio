# Кастомные колонки доски — модель и план работ

**Статус:** план, ничего не реализовано. Отметки: `[ ]` — не сделано, `[*]` — сделано.
Задача без отметки считается несделанной (как в `docs/plugins-plan.md`).

Хотим: у каждой доски свой набор колонок. Кто-то добавит **Отложенные**, кто-то **На ревью**,
кто-то **Бэклог** или **Блок** — и всё это настраивается без пересборки, а карточка сама
понимает, к какому месту жизненного цикла (ЖЦ) относится её колонка.

---

## 1. Главное разделение: ЖЦ — факт, колонка — место

Сегодня колонка не хранится: `boardColumn()` в `packages/shared/src/index.ts` выводит её из
строки сессии (`doneAt` → done, `running` → progress, `waiting|error|closed` → wait,
`idle` без `startedAt` → todo). Это правильная основа, её надо сохранить — **ЖЦ остаётся
фактом, который знает сервер**, а не полем, которое кто-то двигает руками.

Кастомная колонка не может быть «выведена»: «Отложенные» и «На ревью» — это решение
пользователя. Значит, в модели должно быть два независимых слоя:

| Слой | Что это | Кто двигает |
|---|---|---|
| **Стадия ЖЦ** (`todo` → `progress` → `wait` → `done`) | факт сессии, выводится как сегодня | сервер, из хода агента |
| **Место карточки** (колонка) | куда карточка положена на доске | правила колонок + рука пользователя |

Колонка всегда **объявляет, на какой стадии ЖЦ она стоит** (`anchor`) и **как в неё попадают
карточки** (`kind`). Отсюда три вида колонок:

1. **`stage` — дом стадии.** Одна колонка на стадию, карточка попадает туда сама, по ЖЦ.
   У новой доски их ровно четыре и они повторяют сегодняшние Todo / In Progress / Wait / Done.
   Дом **нельзя удалить** — иначе карточке некуда деться. Переименовать, переставить, сменить
   поведение — можно.
2. **`auto` — колонка-правило.** Тоже привязана к стадии (`anchor`), но забирает только часть
   карточек по условию: «то, что агент закончил, — на ревью», «то, что упало, — в ошибки».
   Появилась → карточка уходит из дома в неё; правило перестало совпадать → карточка
   возвращается в дом.
3. **`manual` — ручная колонка.** Карточка попадает туда только когда её туда положили:
   «Отложенные», «Бэклог», «Блок». ЖЦ при этом продолжает идти, и карточка это показывает
   (живой ход, вопрос агента), но с места не уезжает.

Три вида — это и есть ответ на «на каком ЖЦ каждая будет»: в конфиге колонки есть поле
**«Стадия»** (`Не начата / В работе / Ждёт вас / Закрыта / вне ЖЦ`), и оно определяет и
порядок по смыслу, и правила входа.

## 2. Как карточка выбирает колонку

Одна чистая функция в `packages/shared` — её читают и доска, и сервер (очередь автозапуска):

```ts
/** Ключ колонки, в которой карточка стоит на доске. */
export function boardColumnOf(
  facts: BoardTaskFacts,
  columns: readonly BoardColumnDto[],
): string {
  const stage = boardColumn(facts); // ЖЦ — как сегодня, без изменений
  // 1. ручная раскладка живого столбца (со сторожем по сроку — см. «Отложенные»)
  const held = columns.find((c) => c.id === facts.columnId);
  if (held && !holdExpired(facts)) return held.key;
  // 2. правила — в порядке колонок на доске, первое совпадение выигрывает
  for (const c of columns) {
    if (c.kind === "auto" && ruleMatches(c.rule, facts, stage)) return c.key;
  }
  // 3. дом своей стадии — то, что было до кастомных колонок
  return homeOf(columns, stage).key;
}
```

**Инварианты (проверяются тестами и сервером):**

- на каждую стадию ровно один дом (`kind: "stage"`), все четыре стадии всегда покрыты;
- дом нельзя удалить и нельзя спрятать;
- порядок колонок — `sortOrder`; правила смотрятся в этом же порядке, поэтому пересечение
  двух правил разрешается предсказуемо (первая колонка забирает);
- нет ни одной колонки → функция возвращает ровно то, что сегодня возвращает `boardColumn()`
  (доска из прошлой версии после обновления выглядит идентично).

Ручная раскладка (`columnId`) сильнее правил: положил карточку в «Отложенные» — она там, даже
если правило «На ревью» ей подходит. Правила сильнее дома. Дом — всегда последний.

## 3. Схема БД

Новая таблица (миграция — `ensureSchema`, как у остальных):

```
board_columns (
  id           TEXT PRIMARY KEY,
  board_id     TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE,
  key          TEXT NOT NULL,              -- stable slug: todo|progress|wait|done|review…
  title        TEXT NOT NULL DEFAULT '',   -- пусто = подпись из i18n по key (только дома)
  kind         TEXT NOT NULL DEFAULT 'manual',   -- stage | auto | manual
  anchor       TEXT,                       -- todo|progress|wait|done (у manual — подсказка)
  home         INTEGER NOT NULL DEFAULT 0, -- 1 только у четырёх домов
  rule         TEXT,                       -- JSON условия (для kind=auto)
  sort_order   INTEGER NOT NULL DEFAULT 0,
  accent       TEXT,                       -- цвет полоски (фиксированный набор)
  sort_mode    TEXT NOT NULL DEFAULT 'manual', -- manual|created|updated|done
  accepts_prompt INTEGER NOT NULL DEFAULT 1,   -- показывать «Следующий промпт» на карточке
  keep_on_run  INTEGER NOT NULL DEFAULT 0,     -- оставаться здесь, когда агент начал ход
  wip_limit    INTEGER,
  created_at   INTEGER NOT NULL, updated_at INTEGER NOT NULL,
  UNIQUE(board_id, key)
)
```

Плюс три поля на `sessions` (аддитивные `ALTER`, как уже делается для `usage`/`model`):

```
board_column_id TEXT,              -- ручная раскладка; NULL = по правилам и ЖЦ
board_hold_until INTEGER,          -- «отложить до» (этап 6)
board_column_at INTEGER,           -- когда положили (для сортировки ручных колонок)
```

Сидирование: `ensureBoardColumns(boardId)` вставляет четыре дома при создании доски **и** при
первом чтении доски, у которой колонок ещё нет (старая БД). Ключи `todo|progress|wait|done`
сохраняются намеренно: `data-column` в `BoardPage.tsx` и `BoardPage.test.tsx` остаются
валидными, `chat.colTodo…` из i18n — тоже.

## 4. Что происходит с ручной раскладкой (правила перехода)

Семантика Done сегодня — образец для всего остального: промпт, написанный в закрытую задачу,
снимает `doneAt` на сервере (`claimBoardTaskTurn`), и карточка сама возвращается в работу.
Ручные колонки обязаны вести себя так же предсказуемо.

| Событие | Что с `boardColumnId` |
|---|---|
| Пользователь перетащил карточку в `manual`/`auto` колонку | ставится id колонки |
| Пользователь перетащил карточку в дом стадии | `NULL` — «вернуть в ЖЦ» |
| Пункт меню карточки «Вернуть в работу» | `NULL` |
| Начался ход агента (`claimBoardTaskTurn`) | `NULL`, **если** у колонки `keep_on_run = 0` (по умолчанию) — как Done сегодня |
| Колонку удалили | `NULL` у всех её карточек → они падают в дом/правила, сирот нет |
| Карточку удалили | строка уходит вместе с сессией |
| Доску удалили | `board_columns` уходит каскадом |

`keep_on_run = 1` — для «Блок»/«Отложенные», где карточка должна остаться на месте, даже если
агент неожиданно начал ход. Тогда карточка в ручной колонке носит живой значок (пульс
`cardLive`), а не притворяется, что ничего не происходит.

## 5. API

Всё возвращает обновлённый `BoardDto` целиком (как уже делают роуты `folderTags`), чтобы клиент
ничего не склеивал руками.

```
POST   /api/boards/:id/columns           { title, kind, anchor?, rule?, afterId? } → BoardDto
PATCH  /api/boards/:id/columns/:colId    { title?, kind?, anchor?, rule?, sortMode?,
                                           accent?, acceptsPrompt?, keepOnRun?, wipLimit? } → BoardDto
DELETE /api/boards/:id/columns/:colId    (домам — 400) → BoardDto
PUT    /api/boards/:id/columns/order     { ids: string[] } → BoardDto
PATCH  /api/sessions/:id                 { boardColumnId: string | null }  (роут уже есть)
```

Валидация последнего: колонка обязана принадлежать доске этой сессии, иначе 400. Плюс
WS-событие `board.updated { board }` (в `WsServerEvent` его пока нет), чтобы вторая вкладка и
телефон видели новую колонку без перезагрузки — это и есть «динамически».

`BoardDto` получает `columns: BoardColumnDto[]`; `boardColumn()` не трогаем, рядом появляется
`boardColumnOf()`. Серверные потребители раскладки (`listBoardSessions`, очередь
`folderAutoRun`) начинают читать `boardColumnOf`, а не `boardColumn`.

## 6. UI

- **Кнопка «Колонки доски»** рядом с «Папки доски» (низ рейла) → `BoardColumnsDialog` на
  `AppDialog`: список колонок с ручкой перетаскивания, полем названия, селектом **Стадия** и
  селектом **вид** (дом / по правилу / ручная), правилом (для `auto`), лимитом WIP, корзиной у
  неудаляемых — disabled с подсказкой.
- **⋮ в шапке колонки**: переименовать на месте, «Добавить колонку справа», «Настроить»,
  «Удалить». Диалог — тот же, открытый на этой строке.
- **Призрачная колонка «+»** в конце полосы: добавить колонку, не заходя в диалог.
- **Перетаскивание между колонками.** `startTaskDrag` уже есть (мышь — за карточку, палец — за
  ручку). Добавляем горизонтальные цели: подсветка `.column` под указателем, бросок в дом =
  «вернуть в ЖЦ» (подсказка на цели), бросок в ручную = положить. На телефоне, где
  горизонтальный drag конфликтует со скроллом полосы, тот же выбор — пункт меню карточки
  **«Переместить в…»**.
- **Меню карточки**: «Переместить в…» (список колонок), «Вернуть в работу» (когда стоит вручную).
- **Карточка в ручной колонке** показывает состояние ЖЦ: пульс — ход идёт, точка — агент ждёт
  ответа, «Отметить готовой» — как сегодня (Done важнее всего, `doneAt` бьёт любую раскладку).
- **Промпт на карточке** (`isPromptable`) — из флага `acceptsPrompt`, а не из хардкода
  `wait|done`. У «На ревью» он включён: «вернуть на доработку» — это и есть промпт.
- **Сортировка** — `sortMode` колонки. Домашние значения повторяют сегодняшние: done → `done`,
  wait → `updated`, остальные → `manual`.
- **Память прокрутки** (`BoardScrollState.columns`) сейчас ключуется стадией
  `Partial<Record<BoardColumn, number>>` — перевести на id колонки, иначе кастомные теряют
  позицию при возврате из чата.
- **Рейл «Избранное»** и **группировка по проекту** перестают ходить по `COLUMN_ORDER`:
  избранное — в порядке колонок доски, группы по папкам — только у дома стадии `todo`.
- **i18n**: `COLUMN_TITLE` заменяется на `column.title || t(fallbackKey(column.key))`;
  новые строки — диалог, меню, подсказки — в `packages/i18n/src/messages/{ru,en}.ts` **и**
  `apps/web/src/lib/i18n-messages/{ru,en}.json`.
- **CSS**: `.column[data-column="…"]` остаётся ключом; цвет — из `accent` (переменная на
  секции), ширина та же.

Настройки доски в `AppSettings` **не участвуют**: колонки — это данные доски, как папки и
теги, а не настройка установки, поэтому в файл Export/Import они не попадают и `stripSecrets`
их не касается. Если позже захочется «шаблон колонок для новых досок» — это уже настройка, и
её путь описан в скилле `settings-import-export` (пять точек, включая `afterSettingsWrite`).

## 7. Примеры пользовательских наборов

| Хочу | Колонка | Стадия | Вид | Ещё |
|---|---|---|---|---|
| Отложенные задачи | «Отложенные» | вне ЖЦ (подсказка wait) | manual | «Отложить до…» → `board_hold_until`, `keep_on_run = 1` |
| Задачи на ревью | «На ревью» | wait | auto, правило `{ stage:"wait", questionPending:false, hasError:false }` | дом Wait остаётся для вопросов и падений |
| Бэклог на будущее | «Бэклог» | todo | manual | в очередь `folderAutoRun` не попадает — очередь читает только дом todo |
| Заблокировано | «Блок» | progress | manual | `keep_on_run = 1`, живой значок на карточке |
| Мои ошибки отдельно | «Сломалось» | wait | auto, правило `{ stage:"wait", hasError:true }` | до дома wait |

Один и тот же механизм покрывает и «я хочу свои свадебные колонки», и полезное разделение
Wait, которое сегодня склеено в одну колонку.

## 10. Проверка

1. **Юнит (shared).** Таблица «факты ЖЦ × набор колонок → ключ»: четыре дома без кастомных
   колонок дают те же значения, что `boardColumn()`; ручная карточка остаётся на месте при
   смене статуса; правило забирает карточку и отпускает её, когда факт изменился; удалённая
   колонка не оставляет карточку без дома.
2. **Роуты.** Апгрейд старой БД; CRUD; дом не удаляется; чужая колонка → 400; удаление доски и
   колонки; `claimBoardTaskTurn` снимает/не снимает раскладку по `keep_on_run`.
3. **Доска на живом сервере.** Существующая доска после обновления выглядит как раньше →
   добавили «На ревью» (auto, wait) → законченный ход уезжает туда, вопрос остаётся в Wait →
   перетащили карточку в «Отложенные», написали в неё промпт, она вернулась в работу →
   удалили колонку с карточками, они вернулись в дом → вторая вкладка увидела колонку без
   перезагрузки.
4. **Телефон.** Полоса колонок скроллится, «Переместить в…» работает без drag, диалог не
   вылезает за экран.
5. **Скриншоты.** `npm run screens` — дефолтная доска не изменилась; новый кадр с кастомной
   колонкой.

## 11. Риски и края

- **Раздвоение истины.** Очередь автозапуска, избранное и серверные проверки обязаны читать ту
  же `boardColumnOf`, что и рендер, иначе «Отложенные» начнут запускаться сами. Функция живёт
  в `shared`, не в странице.
- **Пропавшая карточка.** Любая ошибка в правилах не должна прятать карточку: дом стадии
  всегда последний фолбэк, поэтому карточка видна всегда.
- **Кастомная колонка прячет живую работу.** По умолчанию ход выдёргивает карточку в progress;
  `keep_on_run` — осознанный выбор, и такая карточка носит живой значок.
- **Дома.** Не удаляются и не прячутся — только переименование, порядок и поведение. Порядок
  домов свободный: «Todo» не обязана быть первой (очередь и «+» ищут её по стадии, не по
  индексу).
- **Два правила на одну карточку.** Побеждает то, что левее на доске; это документируется в
  диалоге подсказкой.
- **Совместимость.** `boardColumn()` остаётся для экспорта чата и старых вызовов; новые поля
  только добавляются; отсутствие строк в `board_columns` — легальное состояние, а не ошибка.
- **Никаких настроек в файле Export/Import.** Колонки — данные доски; в настройки попадёт
  только будущий шаблон, и тогда — по скиллу.

## 12. Что решить перед стартом

1. **Скоуп.** Колонки принадлежат доске (как папки и теги) — так в плане. «Каждому свои» —
   это пользовательский скоуп, которого сегодня нет ни у досок, ни у чатов; делаем ли мы его
   сейчас или откладываем до мультипользовательности?
2. **Правила в v1 или этапом 5?** Ручных колонок достаточно для «Отложенных» и «Бэклога», но
   «На ревью» без правила — это ручное перекладывание каждой карточки.
3. **Перетаскивание между колонками на телефоне.** Меню «Переместить в…» надёжнее; делаем ли
   drag там вообще?
