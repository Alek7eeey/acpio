Три варианта в двух абзацах

VS Code в iframe самый быстрый результат

Даёт буквально всё из списка сразу — сильнее любого самописного варианта. Цена: второй процесс в жизни (~350 МБ), состояние панели вне нашего React, а C# в неофициальной сборке упирается в лицензию расширения (идём через OmniSharp/Roslyn LS).

  • срок: 1–2 дня, включая прокси
  • риск: вес, лицензия C#-расширения, «приложение в приложении»
  • свой UI — только своим расширением: gutter-кнопка некликабельна, инлайн-инпут — через Comments API

Monaco + LSP баланс

Редактор из VS Code и его TS-движок, но UI наш. Языки — через monaco-languageclient: tsserver для TS, Roslyn LS для C#; версии определяет сервер по проекту. oxlint/oxfmt — наши CLI-вызовы в маркеры.

  • срок: 3–5 дней до рабочего TS+C#, ещё день на C#-сервер
  • риск: LSP-мост (JSON-RPC ⇄ WS) — единственная по-настоящему новая часть
  • плюс: инлайн-инпут «спросить про эту строку» — content widget, наш React внутри

CodeMirror 6 самый лёгкий

Тот же LSP-подход (@codemirror/lsp-client), меньше бандл, но свой UI-слой шире: peek-окна, breadcrumbs, quick-fix меню придётся собирать самим. Оправдан, только если вес критичен.

  • срок: 4–7 дней
  • риск: много UI-мелочи, которой у Monaco/VS Code уже готово; контекстное меню — своё с нуля
  • плюс: виджет-инпут — самый простой из трёх (WidgetType.toDOM)
Что общего у всех трёх: настоящая навигация и настоящие ошибки TS/C# приходят не от редактора, а от языкового сервера на сервере (tsserver, Roslyn). Разница только в том, сколько UI отдать нам и сколько клея написать.
